# 启动输出留存：内存中的有界环形缓冲（r34-D6）

日期：2026-10-30。实现：[`src-tauri/src/launch.rs`](../../src-tauri/src/launch.rs)
（`logging_sink` / `launch_output`）、[`src/dialogs/LaunchDialog.tsx`](../../src/dialogs/LaunchDialog.tsx)。

## 1. 问题

`launch://progress` 事件只到达打开着的启动面板；面板关闭后，进程继续跑，输出却没人接。
重新打开面板只能看到进程状态，看不到“刚才为什么退出”。把输出写进活动记录会引入磁盘
持久化与敏感内容问题，所以本轮选择**内存、按会话、按仓库**保留最后一次运行。

## 2. 设计

- 每个仓库最多 500 行；会话内最多 200 个仓库；超出时先淘汰最旧仓库。
- 每次新的启动命令创建一个 `logging_sink`，它先清空该 slug 的旧记录，再在转发原
  progress 的同时追加 `[stage] message`。面板关闭不影响线程继续写。
- `launch_output(slug)` 只读返回；`LaunchDialog` 打开时若本地还没有新输出，就把这份
  快照填入输出区，前面加一行“— 上次运行的输出 —”。
- 不落盘、不进活动记录、不写 config。应用退出即消失。

## 3. 验证

- `cargo test --lib launch_log`：行数上限、旧记录清空、包装的 sink 仍转发、slug 上限。
- `launch_output` 是异步命令；前端在挂载 effect 里调用，失败静默（旧输出不是关键路径）。
- 未在真机启动一个进程后关闭/重开面板；Rust 单元测试与类型检查覆盖。

## 4. 边界

- 输出可能含用户程序打印的敏感值；因此**只在内存**、只保留最后一次、最多 500 行。
  这不是审计日志，也不能作为“所有历史输出”的承诺。
- 多进程同时运行时，快照只保留最后一次 `logging_sink` 创建后的行；同时启动两个实例
  的语义没有单独测试。
- 跨应用重启不保留，这是刻意的：一次崩溃后的旧输出不应悄悄留在下一会话。
