# MCP 协议修订与新增只读工具（r33-D9）

## 1. 协议修订：2025-06-18 → 2025-11-25

核实来源（均为官方 `modelcontextprotocol.io`，2026-10-30 抓取）：

- `specification/2025-11-25` 存在，章节为 Architecture / Base Protocol / Server Features /
  Client Features。
- 该修订的 lifecycle 仍要求：客户端发 `protocolVersion`；服务器支持请求版本就回同一版本，
  否则回自己支持的最新版本；客户端不接受时自行断开。
- changelog 摘要：stdio 服务器可用 stderr 记录；tools/resources/prompts 可带 icons；
  elicitation 支持带标题/默认值的枚举。

决定：`PROTOCOL_REVISION = "2025-11-25"`，`SUPPORTED_PROTOCOL_VERSIONS` 同时保留
`2025-06-18`。不实现 icons（没有可提供的图标 URL）与 elicitation（服务器不向用户提问），
因此没有借新版名义增加未实现能力；旧客户端仍协商到它认识的修订。

测试：`tests/mcp-server.test.ts` 的初始化用例断言：客户端请求 `2025-06-18` 时回
`2025-06-18`；请求不支持的 `2024-11-05` 时回 `2025-11-25`。全部 32 条 MCP 测试通过
（`node --experimental-strip-types --import ./tests/helpers/register.mjs --test tests/mcp-server.test.ts`，
2026-10-30）。

## 2. 新工具一：`devhub_repo_commits`

只读 `git log -n <1..50>`，参数数组、`--no-pager`、8 s 超时、1 MiB 输出上限。
三种状态分开：`ok` / `no-git`（目录没有 `.git`）/ `empty`（空仓库或无可读历史）/ `error`。
没有 `.git` 不等于空仓库——前者是压缩包下载或手工复制，后者是还没提交。

测试用真实仓库：`.mcpfixtures/container/hist_owner` 首次运行时 `git init` + 一次提交
（之后复用），断言 subject/author/40 位哈希/ISO 日期；`alpha` 断言 `no-git`；未知 slug
是 JSON-RPC `-32602`。

## 3. 新工具二：`devhub_search_local`

在一个仓库或全部仓库（上限 100）中按行搜索文本。默认字面量、忽略大小写；`regex: true`
时用 JavaScript 正则。只读、无网络；跳过 `.git`/`node_modules`/`target` 等目录、符号链接、
二进制（前 8 KiB 含 NUL）与超过 1 MiB 的文件。上限：2 000 个文件、200 行命中、10 秒；
任一项触顶都在 `truncated` / `timedOut` 中说明，而不是把“没扫完”说成“没有”。

测试：alpha 里的 `export const util` 命中 `src/lib/util.ts`；`should not be listed`
（只存在于 `node_modules`）必须 0 命中；非法正则是 `-32602`。

## 4. 边界与未验证

- 两个工具都只读：不写文件、不启动进程、不发网络请求；annotations 也按真实行为写。
- `devhub_repo_commits` 依赖 PATH 上的 `git`；找不到时返回 `error`，不会伪装成空历史。
- 未在真实 MCP 客户端（Claude/Cursor/Qoder 等）里驱动新工具；协议层测试用真实 stdio
  子进程完成，客户端兼容性未验证。
- 图标、elicitation 未实现；若未来实现，需要先提供可访问的图标资产与明确的提问边界。
