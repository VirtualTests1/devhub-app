# 托盘与系统通知可行性（r28-R2）

状态：**本轮不实现托盘/系统通知；保留已有的任务栏注意力提示。**
调研日期：2026-10-28。

## 来源

- Tauri 2 system tray：<https://v2.tauri.app/learn/system-tray/>（2026-10-28 抓取）。
- Tauri 2 notification 插件：<https://v2.tauri.app/plugin/notification/>（2026-10-28 抓取）。

## 事实

- Tray 需要 Cargo 的 `tray-icon` feature，使用 `TrayIconBuilder` 创建图标与菜单；Linux 上事件支持不完整。
- 通知插件文档说明 Windows 上只对**已安装应用**可靠工作；开发模式下会显示 PowerShell 的名称与图标。本应用当前是绿色目录运行，不是安装应用。
- 当前已有 `requestUserAttention` 任务栏提示（r27-N3），不新增依赖即可覆盖“窗口失焦时完成”的场景。

## 方案比较

| 方案 | 收益 | 成本/风险 | 结论 |
|---|---|---|---|
| 保持任务栏提示 | 无新依赖，已上线 | 只闪任务栏，不是通知中心消息 | 保留 |
| 托盘图标 + 菜单 | 快速显示/隐藏、退出 | 生命周期、单实例、关闭到托盘语义、图标资源与 GUI 验证 | 暂不采用 |
| 系统通知插件 | 通知中心可见 | 需要安装形态；Windows 开发模式显示 PowerShell 图标，绿色版语义不诚实 | 暂不采用 |

## 可执行集成方案（若后续重开）

在已安装（MSI/NSIS）形态具备后，用 feature flag 增加托盘：菜单只做显示/隐藏、退出；关闭窗口默认仍关闭程序，新增的“关闭到托盘”必须是显式设置；单实例插件把第二实例的深链转给现有窗口。验收需要真机点击与关闭/重启演练，不能只用源码契约测试。

## 未验证

托盘点击、关闭到托盘后的进程生命周期、Windows 通知在绿色版与安装版下的实际表现均未验证。
