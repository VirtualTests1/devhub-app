# DevHub 使用指南

面向"我要把它跑起来试用"的人。三种方式，按省事程度排列。

---

## 方式一：直接用便携版（不需要装任何东西）

**适用**：只想试用界面和功能。
**前提**：Windows 10/11 64 位。

1. 解压 `DevHub-0.3.0-portable.zip` 到任意可写目录（**不要放 C:\Program Files**，Windows 不允许应用往那里写数据）。
2. 双击 **`启动 DevHub.bat`**。
3. 首次启动会检查 WebView2 运行时。Windows 10/11 通常已自带；若提示缺失，双击同目录的 `MicrosoftEdgeWebview2Setup.exe` 装一次即可。
4. 若提示**未找到 Git**，点界面上的「自动安装内置 Git」——它会把便携版 Git 装到应用自己的目录，约 57 MB 下载、400 MB 磁盘、2–3 分钟，**不需要管理员权限**，也不碰你系统里已装的 Git。

**你的项目会放在哪**：默认在应用目录下的 `项目\`。想改到别处，进「设置 → 项目目录」，
点「浏览…」选目录，**或者直接输入路径后按回车 / 点一下别处**——改完立刻生效，不需要重启，
也不会在刷新后被打回原值。

每个仓库的最终位置是 `项目\<仓库名>_<拥有者>`（例如 `项目\opus-video-prompts_joeseesun`），
**一仓一目录，互相隔离**。`cache\`（封面图）和 `venvs\` 是应用自己的目录，不会被当成项目。

> 旧的 `0.2.0` 会落成 `项目\code\github.com\<owner>\<repo>`。**已经下载的仓库不用搬**：
> 两种布局都会被识别、列出并能正常打开。

## 0.3.0 相对 0.2.0 的变化（只看得到、用得上的部分）

- **窗口没有系统标题栏了**：顶部一条自己的标题栏可拖动，双击切换最大化，右侧是最小化/最大化/关闭。
  侧边栏可收成图标栏（点标题栏左侧的按钮），边缘拖拽可调宽窄。
- **记录页能看懂了**：每条记录写清"改了什么、从什么变成什么、在哪个界面做的、动了哪个路径"；
  同一个对象的多次调整折成一组（"5 次"可展开）；支持**回退**、**批量选择删除**、导出 Markdown/JSONL；
  保留时长、计划清理（每天/每周/手动）与时间显示格式都在这一页里改。
- **回退会动磁盘，所以有确认**：回退一条"下载仓库"= 删掉它下载的目录（连同 venv 与工作区副本），
  弹的是系统对话框并写明完整路径；回退一条"删除项目"= 按记录里的地址重新克隆。
  只有被应用识别为项目的目录才允许这样删除，`venvs\`、`cache\`、`_worktrees\` 这些应用自己的目录一律拒绝。
- **常用页**：按你实际用过的次数自动汇总项目与设置项，钉选的排在最前。
- **外观并入设置**：左侧"外观"仍然可点，会跳到设置里对应的一节并高亮一下。
- **项目页可筛选可搜索**：按名称/拥有者/路径搜索，"打开过 / 没打开过"筛选，可按拥有者分组。
- **下载可以并行**：添加页的队列按任务分别显示进度、日志与结果，并发数在设置里调（1–6，超出上限的任务排队）。
- **网络链路各自可选**：搜索与下载各有"逐层尝试 / 只用直连 / 绕过 hosts"等策略；
  底部状态条会说明当前走的是哪条链路、hosts 被哪个工具改了几条，以及"绕过不可用（无公网地址）"这类真实结论。
  状态条点空白处或按 Esc 收起；双击某一项会跳到对应的设置项。
- **开发者模式**：设置 → 界面区块 → 前往开发者模式。开启后点任何一块都能改它的显示、尺寸档位、顺序、
  位置与 CSS；这些改动都是"显示层"的，导出/导入即可迁移，不影响数据。
- **启动面板**：运行中是一个可操作的常驻状态（停止 / 挂起 / 恢复），多步骤启动可勾选"逐步确认"，
  标题可点进仓库主页，路径与"在资源管理器打开"移到标题下方。
- **报错不再乱码**：curl/git 的中文错误按系统 OEM 代码页解码显示，并会补一句可操作的建议。

## 方式二：从源码运行（改代码时用，有热重载）

**适用**：要改界面 / 调样式，改完立刻看到效果。

**前提**（一次性）：
- Node.js 22 + pnpm
- Rust 工具链（`x86_64-pc-windows-msvc`）

```powershell
cd <项目目录>

. .\env.ps1          # 必须！每次开新终端都要先执行这一行
pnpm install         # 首次
pnpm tauri dev       # 启动
```

**`. .\env.ps1` 不能省。** 这台机器上 Visual Studio 的 `vcvars64.bat` 是坏的，`env.ps1` 负责手动定位 MSVC 工具链与 Windows SDK。不执行会报找不到 `cl.exe` / `link.exe`。

**关于运行方式的坑**（都踩过，其中一条本轮实测后改正了）：

| 做法 | 结果 |
|---|---|
| `pnpm tauri dev` | ✅ 正确，也是唯一推荐的方式。CLI 负责起 dev server、注入 devUrl、监听文件 |
| 只跑 `pnpm dev` 再手动跑 `target\debug\devhub-app.exe` | ⚠️ **能渲染**（2026-10-07 实测：devUrl 是编译进 debug 构建的，只要 1420 端口有人接着就显示）。但它不带 CLI 的重启与文件监听，改 Rust 不会自动重来，所以只适合"我要自己控制两端"的调试场景 |
| 不开 dev server 直接双击 `target\debug\devhub-app.exe` | ❌ 白屏，1420 没人应答 |
| 手动跑 **release** exe 想看界面 | ❌ 走的是 `dist\`，改动不热重载；要试新功能请重新打包 |

**开发版的数据在哪**：debug 构建的 `devhub-config.json` 与 `devhub-activity.jsonl` 落在
**`src-tauri\`** 下（`bundled_runtime_dir()` 在 dev 布局下回退到 `CARGO_MANIFEST_DIR\runtime`，
配置取它的父目录），不是 `target\debug\`。往 `target\debug\` 里写记录是无效的——应用不读那里。
同理，`tauri dev` 监听 `src-tauri`，改这两个文件会触发重建并关掉窗口。

**样式预览切换器**：开发模式下，左侧栏底部有「样式预览」，可实时切换三套视觉方向（柔和 / 硬朗 / 醒目）。**正式打包不包含它**（只在 `import.meta.env.DEV` 下渲染）。

关掉：在终端按 `Ctrl+C`；或关窗口。若端口 1420 被占：
```powershell
Get-NetTCPConnection -LocalPort 1420 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

## 方式三：自己重新打包便携版

**适用**：改了代码，想出一个能发给别人的绿色包。

```powershell
cd <项目目录>

. .\env.ps1
pnpm tauri build --no-bundle          # 约 10 分钟（LTO 优化），产出 release exe
.\scripts\pack-portable.ps1           # 版本号默认取 package.json，也可 -Version 0.3.0 指定
```

产出：`.pack\DevHub-<版本>-portable.zip`（含启动脚本、使用说明、WebView2 安装器）。
脚本会**校验** WebView2 安装器的微软签名，验不过就拒绝打包。

`--no-bundle` 跳过 MSI/NSIS 安装包——需求里明确不要安装包，只要绿色版。

## 出问题时怎么查

### 界面白屏
第一次打开是空白，99% 是**运行方式错了**：用了 `pnpm dev` 或手动双击 exe。
→ 改用 `pnpm tauri dev`。
若确实是运行时报错，界面会直接显示**红色错误文字与调用栈**（内置了错误边界，不会静默白屏）。

### 想确认功能是否正常（不用点界面）
程序内置无头自检，可直接在终端跑：

```powershell
$exe = ".\src-tauri\target\debug\devhub-app.exe"

& $exe --env-check 5          # 环境探测耗时（应 < 1500 ms）
& $exe --cover-check rust-lang/rust   # 封面图抓取 + 缓存命中
& $exe --settings-check       # 设置读写往返（含重启后是否沿用已保存开关）
& $exe --search-check "rust http client"  # GitHub 搜索
& $exe --clone owner/repo     # 四层降级下载
& $exe --launch-check         # 启动命令识别
```

**验证"没有终端黑窗"**：用 **release** 版 exe（debug 版本身带控制台，测不出来）。一边盯着屏幕，一边跑：

```powershell
$exe = ".\src-tauri\target\release\devhub-app.exe"
& $exe --spawn-check          -- cmd /c ping -n 5 127.0.0.1   # 静默：不应出现窗口
& $exe --spawn-check --visible -- cmd /c ping -n 5 127.0.0.1  # 故意不加标志，作为对照
```

`--spawn-check` 就是为此加的：它按应用内部完全相同的方式启动一个子进程，`--visible` 版本
**故意省略** `CREATE_NO_WINDOW`，用来对比。⚠️ 诚实说明：在开发这台机器的自动化环境里，
两种版本都没能生成控制台窗口，所以**对照组不成立**——自动化环境本身抑制了窗口创建。
要确认这一点，请在你自己双击启动的应用上观察，或直接看代码：所有 12 处 spawn 都走
`proc::silent`（`src-tauri/src/proc.rs`，附带单元测试）。

**关于"UAC 提权"**：应用自己**从不申请提权**。实测过所有它能启动的程序：

| 程序 | 提权要求 |
|---|---|
| `devhub-app.exe` | 无（清单里没有任何提权声明，也没有"以管理员身份运行"兼容性标记） |
| 内置 Git 的自解压包 `PortableGit-*.7z.exe` | `asInvoker`（我把真实发布包的前 2 MB 拉下来读了清单） |
| `MicrosoftEdgeWebview2Setup.exe` | `asInvoker`，且**只有**在系统缺 WebView2 时启动脚本才会调用它（本机不缺） |
| `git` / `curl` / `netstat` / `tasklist` / `pwsh` / `code` | 均无 |

应用现在会**报告自己是否处于提权状态**，直接回答这个问题：

- 底部状态条点开后有一行「进程权限：标准用户（未提权）」或「已提权（管理员）」；
- 或终端跑 `& $exe --env-check 3`，输出里有 `elevated = false/true`。

如果显示 **已提权**，说明是从外部以管理员方式启动的（右键"以管理员身份运行"、快捷方式打了勾、
或你同意过某个提权弹窗）；如果显示**标准用户**，那弹窗就不是 DevHub 引起的。

### 界面验收（驱动真实窗口做断言，不依赖截图）
```powershell
# 终端 A：带调试端口启动
. .\env.ps1
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = '--remote-debugging-port=9222'
$env:DEVHUB_PROJECT_ROOT = "$PWD\.cdpfixtures"
pnpm tauri dev

# 终端 B：跑全部场景
pwsh -NoProfile -File .\scripts\verify-fixes.ps1
```

`scripts/verify-fixes.ps1` 通过 **Chrome DevTools Protocol** 驱动真实的 WebView2，逐个场景断言
真实 DOM、真实计时与真实落盘结果（`scripts/cdp.mjs` 是极简 CDP 客户端，场景在
`scripts/scenarios/`）。加 `-Network` 才包含需要连 github.com 的场景——这台机器对 `github.com:443`
的连通性是间歇的（`api.github.com` 正常，`github.com` 会超时），所以默认走**不依赖网络**的等价场景。

另有上一代的 `verify-ui.ps1`（组件探针版），保留但已不是首选：它靠探针组件 + 截图读结果，
而截图在本项目里被证明不可靠（同一份代码两次截图内容不同、`PrintWindow` 会漏抓区域）。

### 截图
```powershell
pwsh -NoProfile -File .\scripts\capture-ui.ps1 -Width 1200 -Height 860 -Name my-shot
```
输出到 `.shots\my-shot.png`。这个脚本自己管理 dev 进程生命周期，不会残留后台进程。

## 安全说明（这些行为是有意为之，不是偷懒）

- **不改你的全局 git 配置**。代理与 IP 钉死只通过 `-c` 参数作用于**单次调用**。
  可自行验证：`git config --global --get http.proxy` 应为空。
- **不关闭证书校验**。IP 钉死保留了主机名与 SNI，所以证书照常验证。
  实测用假主机名会报 `SEC_E_WRONG_PRINCIPAL`，证明校验确实开着。
- **镜像默认关闭**。开启后界面上会有琥珀色标注，因为代码会经由第三方服务器传输。
- **第三方镜像只能用你配置的源**，应用不会自己架设代理。
- **删除项目要手动输入仓库名确认**，且不可恢复。
- **清理缓存只删依赖与构建产物**，源码、`.git`、你自己的改动都不会被碰。
- **GitHub Token 用 Windows DPAPI 加密后写入配置文件**，只有当前 Windows 用户能解密；设置页会显示配置文件路径。仍建议使用权限最小的 Token。
